# hxyfront-62012 染整离线作业台

面向纺织染整车间的离线作业台：复染批次、染缸槽位、客户订单三本账，开工前统一排产，
依据（配方/后整理/复修原因）改版后旧结论立即失效，断网可录工艺曲线、联网自动合并。

## 业务规则落地

| 需求 | 实现 |
| --- | --- |
| 开工前按坯布重量、浴比和槽位余量分配母液 | `scheduleDrafts`：需求 = 重量 × 浴比，母液按编号 FIFO 扣减 |
| 母液不足或槽位撞单 → 留待排并写明冲突 | 草稿保持 `draft`，写 `liquor_shortage` / `slot_overlap`，不足时不预占母液 |
| 两名技术员同槽位先到者占用 | 按接单时间（并列按客户端序号）先到先得，后到留冲突草稿并记录占用者 |
| 配方/后整理/复修原因一变，旧色差与评审失效重算 | `bumpBasis` 版本 +1，依附旧 rev 的色差/评审立即清空，须重测重评后才能放行 |
| 已签订单保留当时依据 | `signOrder` 签订时冻结配方/后整理/复修原因/色差/评审快照，后续改版不影响 |
| 断网录入工艺曲线、联网后合并 | 离线写操作入队，`FLUSH` 时 `mergeCurveOps` 合并 |
| 同号重放只认首次 | 每条曲线维护 `appliedOps`，重复 opId 直接忽略 |
| 字段两边都改过 → 留双方 | 基于共同祖先判定：单侧改取改动侧；两侧改成不同值则记入 `conflicts` 待人工裁决 |
| 旧批次缺母液编号则升级 | `upgradeLegacyBatches` 补登编号并扣库存 |
| 迁移失败后恢复最近草稿 | 迁移前整体快照；编号不存在等失败时整批回滚到快照 |

## 结构

- `src/engine.ts` —— 纯函数规则引擎（无 React/DOM 依赖）
- `src/types.ts` —— 领域模型（母液、槽位、批次、订单、曲线、迁移）
- `src/store.tsx` —— reducer + localStorage 持久化 + 在线/离线队列
- `src/seed.ts` —— 演示数据（含一个缺母液编号的旧批次 OLD-2599）
- `src/panels/*` —— 批次开工 / 母液台账 / 槽位 / 订单 / 离线曲线 / 旧批升级
- `src/engine.test.ts` —— 36 项断言，覆盖上述全部规则

## 本地运行

```bash
npm install
npm run dev      # http://localhost:62012
npm test         # 规则引擎断言（esbuild 即时打包后用 node 运行）
npm run build    # tsc --noEmit + vite build
```

数据存于浏览器 `localStorage`（键 `dye-bench-state-v1`），右上角"重置"可恢复演示数据。

## 快速验收路径

1. **撞单**：提交一个占用 S1-A 08:00–12:00 的批次（与 RC-2601 重叠）→ 落入"待排冲突草稿"。
2. **母液不足**：提交重量 100kg、浴比 10 的批次 → 写明尚缺 620L，且不扣母液。
3. **先到先得**：两个同槽位同时段批次，接单序号小者开工。
4. **结论失效**：在 RC-2601 上改配方 → 色差/评审标记失效；重测合格、重评通过后才能签订单。
5. **订单冻结**：签订 CO-77 后再改批次配方，订单仍显示签订时 rev.1 依据。
6. **离线合并**：离线曲线页点"一键演示双改冲突" → 同字段双方 135/140 都保留；同号重放被忽略。
7. **升级回滚**：旧批升级页对 OLD-2599 选合法编号成功；用不存在编号（如 ML-404）演练失败回滚。
