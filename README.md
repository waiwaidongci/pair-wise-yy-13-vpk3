# hxyfront-62012 纺织染整离线作业台

源提示词编号：7

纺织染整实验室的**离线作业台**。把分散记录的复染批次、染缸槽位、客户订单打通，
实现开工前母液/槽位分配、并发槽位冲突草稿、版本失效重算、断网曲线合并、
旧批次迁移升级与草稿恢复。

## 业务规则

- **开工前分配**：按坯布重量 × 浴比 测算染液体积，再按配方母液系数分配母液、核对槽位余量；
  母液不足或槽位撞单/余量不足 → 留待排并写明冲突，仍可"先开工"。
- **并发占用**：两名技术员同时提交同一槽位，先到者占用，后到者保留冲突草稿（不丢弃），槽位空出后可补占用。
- **版本失效**：配方、后整理或复修原因一变，依附旧版本的色差结论与评审立即失效并重算；
  已签订单保留签订时依据（快照），不受后续重算影响。
- **断网合并**：断网时录入工艺曲线进入待合并队列；联网后合并，同号重放只认首次（跳过重复），
  字段两边都改过则保留双方值。
- **迁移升级**：旧批次缺母液编号时自动升级补号；迁移前保存最近草稿，迁移失败则恢复最近草稿。

## 技术栈

React + Vite + TypeScript（纯前端，状态持久化到 localStorage，网络状态用 `navigator.onLine` + 手动模拟）

## 本地运行

```bash
npm install
npm run dev
```

## 目录

- `src/types.ts` — 领域模型（批次、配方、后整理、复修原因、母液、槽位、订单、工艺曲线、冲突草稿、草稿快照）
- `src/logic.ts` — 核心业务逻辑（分配、先到占用、版本失效、断网合并、迁移升级）
- `src/store.tsx` — 全局状态（Reducer + Context + 本地持久化 + 网络监听）
- `src/seed.ts` — 种子数据
- `src/components/` — 总览、批次、染缸槽位、客户订单、工艺曲线、版本变更、母液/冲突 页面
- `scripts/verify-logic.ts` — 核心业务规则验证脚本（`npx tsx scripts/verify-logic.ts`）
